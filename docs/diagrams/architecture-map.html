03

The command tree, prerequisites & “dynamic” gating

Hierarchy = scope.parent (≡ SRGS rule-refs, HTN↔CFG). Prerequisite = scope.requires(ctx).

authored — the tree
worklist ─┬─ case.open
         │    └ requires: worklist mode
case-open ┼─ findings.dictate
         │    └ findings.differential
         │      parent: findings · requires: selection
editing ──┼─ report.generate_impression (async)
signing ──┴─ report.sign_and_next
            └ confirm: 'always' ⚠ destructive
scope.parent  = the TREE (≡ SRGS <ruleref>, HTN↔CFG isomorphism)
scope.requires = PREREQUISITE guard (≡ VoiceXML FIA cond)
Chaining = a state-machine problem, not a grammar one
runtime — the hot path (must be cheap)

Gate / swap pre-compiled, per-mode active set

pointer swap on mode change (µs) + scope.requires(ctx) as a runtime mask
⚠ NOT a recompile. A literal per-utterance/per-state grammar recompile (Kaldi HCLG determinize/minimize, or a Rhino .rhn retrain) costs seconds — fatal to the <100 ms budget. “Dynamic” must mean gate/swap.
Smaller active set = faster + fewer false-accepts. Reachability is a hard gate — contextual biasing only boosts, it never excludes.
Prerequisite not met →
├─ auto-satisfiable: silently run establishing cmd, resume (Rasa call/return)
└─ state-changing: PROMPT / CONFIRM ⚠ default for medico-legal safety
